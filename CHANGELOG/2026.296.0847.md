# 2026.296.0847 — feat(skills)!: the eight `charly <pod-verb>` skills live beside the plugin that serves them

## Summary

`pod-charly-core` is a skills-only carrier — measured: **0 `.go`, 0 `.cue`, 0 candy
directories** — so the eight skills documenting `charly start|stop|config|update|
logs|remove|service|shell` were authored, reviewed and tagged in a repo that contains
none of the verbs they document. Under `AGENTS.md` Part II #5 ("a skill lives with the
code, plugin, or config it describes") they move to the repo whose candy **declares
those commands**.

**The gate, per skill (opencharly#606):** the entity comes from the skill's own prose,
never from its name; then where that entity exists; then the negative control.

| skill | the entity its own prose names | where it exists (measured) |
|---|---|---|
| `charly-config` | `charly config` — quadlet/secrets/volume setup | `command:config` → `plugin-pod/candy/plugin-pod/charly.yml` |
| `charly-update` | `charly update` — redeploy + restart | `command:update` → same |
| `logs` | `charly logs` | `command:logs` → same |
| `remove` | `charly remove` | `command:remove` → same |
| `service` | `charly service` | `command:service` → same (`service_resolve.go`) |
| `shell` | `charly shell` | `command:shell` → same |
| `start` | `charly start` | `command:start` → same |
| `stop` | `charly stop` | `command:stop` → same |

All eight command words are declared by **this** candy's `providers:` block. The
`charly <verb>` CLI is a COMMAND-class plugin surface, not core's — the same split
opencharly/plugin-box#59 established for the twelve `charly box` verbs, and the shape
opencharly/pod-ollama#7 worked first.

**What is in this diff**

- 8 skill bodies, byte-identical to the carrier's (`sha256` per skill below).
- 8 **routing-only** `skill:` nodes in `candy/plugin-pod/charly.yml` —
  `name`/`family`/`owner`, no inline `description:` and no `content:` (an inline body
  that disagrees with its file is a hard error in the marketplace generator).
- `family: core` is **kept unchanged**, so every existing `/charly-core:<name>`
  address and every cross-reference to it still resolves; `owner:` becomes
  `plugin-pod`, which is what makes the bodies readable at
  `<repo root>/.agents/skills/<name>/SKILL.md`.
- Two falsified claims corrected in the same commit: `AGENTS.md` and `README.md` both
  said the candy carries **three** skill entities and that the registry-bound verbs'
  reference was "owned by `pod-charly-core`".

**Producer-first.** Nothing is deleted from `pod-charly-core` here: its node removal,
its `README`/`AGENTS.md` and its retirement belong to the session that claimed both
carriers (opencharly/opencharly#600), and the `marketplace` refs switchover is the leg
that proves the relocation end to end. This PR is the ADD half only.
