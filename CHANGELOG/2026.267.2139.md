# 2026.267.2139 — fix(pod): scope remove --purge / volume list to the deploy's own volumes

## Summary

Consumer half of the volume-scope fix (sdk `opencharly/sdk#280`, landed as
`v0.2026267.2130`). Adopts the sibling-safe predicate in `plugin-pod`, closing
the pod-side data-loss on `charly remove --purge` / `charly volume list`.

### The defect

A base deploy's volume prefix (`charly-<base>-`) is itself a prefix of every
sibling instance's volume name (`charly-<base>-<instance>-<vol>`), and podman's
`volume ls --filter name=` is a **substring** match. Scoping by prefix alone
therefore touched a **live sibling instance's** volumes:

- `charly remove --purge <base>` deleted `<base>/<instance>`'s state/storage volumes and its gocryptfs cipher dirs;
- `charly volume list <base>` listed them.

### The fix

- One shared `ownedDeployVolumes` filter (R3) feeds **both** `removeVolumes` and
  `VolumeListCmd`, using `deploykit.SiblingVolumePrefixes` +
  `deploykit.VolumeNameBelongsTo` (longest-prefix-wins) from the new sdk release.
  The helper reads the live deploy config (via the `loadPodDeployConfig` var seam)
  and otherwise performs no I/O; it falls back to the bare prefix when the config
  is unreadable (the orphaned-deploy case).
- `purgeDeployArtifacts` passes its executor-loaded config explicitly to
  `deploykit.RemoveEncryptedVolumesWithConfig`. **This is load-bearing:** the bare
  `deploykit.LoadDeployConfig` is a documented *silent no-op out-of-process*
  (`candy/plugin-pod` **is** out-of-process), so the encrypted purge would
  otherwise see no siblings and keep over-matching — caught by the live proof
  below. Same seam discipline `resolveSidecarNames` already follows.

Dependency: `github.com/opencharly/sdk` bumped `v0.2026266.623 → v0.2026267.2130`
(the merged fix); `go mod tidy` clean, no `replace`.

## How tested

### Live end-to-end proof on a `disposable: true` target

Isolated `CHARLY_DEPLOY_CONFIG` with the marker present:

```yaml
version: 2026.261.1747
app:      {pod: {image: app, disposable: true}}
app/no-1: {pod: {image: app, disposable: true}}
app/no-2: {pod: {image: app, disposable: true}}
other:    {pod: {image: other}}
```

Built charly with the fixed `plugin-pod` + `sdk` compiled in; real podman
volumes + real gocryptfs cipher dirs.

**Pre-fix:**
```
$ charly remove app --purge
Removed volume charly-app-no-1-state / -storage
Removed volume charly-app-no-2-state / -storage
Removed volume charly-app-state / -storage
Removed encrypted volume no-1-secrets / no-2-secrets / secrets
$ podman volume ls …            → charly-other-state   # siblings DESTROYED
$ ls $CHARLY_ENCRYPTED_STORAGE_PATH → charly-other-secrets
```

**Post-fix (this PR):**
```
$ charly remove app --purge
Removed volume charly-app-state
Removed volume charly-app-storage
Removed encrypted volume secrets
$ podman volume ls …            → charly-app-no-1-state, charly-app-no-1-storage,
                                  charly-app-no-2-state, charly-app-no-2-storage,
                                  charly-other-state
$ ls $CHARLY_ENCRYPTED_STORAGE_PATH → charly-app-no-1-secrets, charly-app-no-2-secrets,
                                      charly-other-secrets
```

Only the base deploy's own volumes/dirs are removed; every sibling and the
unrelated deploy survive.
