# 2026.332.0049 — fix(pod): read a namespace-qualified deploy address by D-REF-1, not as one bare box

## Summary

Fixes the behaviour behind opencharly/spec#450: a **namespace-qualified deploy address** was read as
one bare box, so every name derived from it missed.

Measured from the umbrella root on a namespace-imported bed:

```
[update] FAIL
charly: error: command "stop": … no container with name or ID
  "charly-kde-vnc-cdp.check-kde-vnc-cdp-pod" found: no such container
```

while the unit start had created `charly-kde-vnc-cdp-check-kde-vnc-cdp-pod`. Both names come from ONE
identity written two ways: the deploy command's ADD dispatch carries the deploy **key**
(`ns/entity`), the lifecycle commands carry the user's **address** (`ns.entity`), and
`deploykit.CanonicalizeDeployArg` splits only `/` — so the dotted address became a single box.

**DESIGN already owns the rule:**

- **D-REF-1** — "a dotted name's first segment is a namespace if one with that name exists, otherwise a
  node of this project";
- **D-LOAD-6** — "the scope a reference resolves in is the document it is written in".

`resolveDeployAddress` applies it at the **seven** lifecycle commands that take a deploy address —
`start`, `stop`, `restart`, `logs`, `remove`, `shell`, `update` — and `restart` is in that list because
the first round MISSED it (it was the one neighbour that never canonicalized at all; see round 2). The namespace TABLE decides, never the shape of the
string: a dotted **nested path** whose head is a plain node keeps walking, an explicit `-i` keeps its
split, and a project that cannot be read is **reported** instead of guessed through.

### Spike — the exemption, named, and why it applies

The candidate set is the one spec#450 names, labels included: **(a) normalise the dotted address to
the slash deploy key — withdrawn**, and **not** on taste: §2 **identity** makes the dotted path the
node's identity ("prefixed with `<namespace>.` when reached through an import") and D-REF-1 makes its
first segment a namespace, so (a) would invert both and add the second spelling D-LAW-1 forbids;
**(b) interpret the dotted address by D-REF-1 against the namespace table — implemented**, which is
this diff. The evidence for (a)'s withdrawal is the contract text plus the measured names below, which
is what spec#450 records.

What this change needs is not a candidate spike but **the boundary executed**: the live bed run below
is the spike-equivalent — the exact failing boundary (`update` → `stop` name lookup) run end to end,
with the real binary, on a `disposable: true` target. Before it, the same phase failed with the
container-not-found error quoted above; after it, the phase passes.
