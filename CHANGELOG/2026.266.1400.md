# 2026.266.1400 — feat: relocate the check-pod bed from distro-fedora

## Summary of changes

Relocate the `check-pod` R10 bed from `distro-fedora` into the repo that owns the pod runtime/mechanism it tests — this plugin. Four files:

- **`charly.yml`** — makes this repo a real PROJECT so its own entities are gated, and declares the relocated bed:
  - adds `defaults:` (`platform: [linux/amd64]`, `tag: auto`, `registry: ghcr.io/opencharly`, `build: [rpm]`, `merge: {auto: false, max_mb: 128}`) — the build/registry/merge defaults the relocated fixture image needs to build; this is a build-emission change, not a no-op.
  - adds `discover: [candy, box]` — `box` is what makes the relocated fixture a discovered, gated entity (the repo previously scanned only `candy`).
  - bumps `version:` `2026.232.0520` → `2026.249.2125` (the schema stamp the relocated bed's fixture and plan are authored against).
  - declares the `check-pod` bed (kind:pod, `disposable: true`) with its `status-shows-pod` host-side `charly status --json` step, and corrects the bed `description:`'s stale wall-clock from `~110s` to the measured `~275s` (prose-only; see the timing reconciliation below).
- **`box/check-pod/charly.yml`** — the fixture image the bed deploys: a two-layer `fedora-minimal:43` image composing the check-base / check-stack layers plus the plugin-example build-time / builder / verb witness candies, with its own baked plan. Its description now states the bed's actual kind (`kind:pod`, not `kind:check`), matching the `pod:` declaration in `charly.yml`. It moves WITH the bed because a bed's `image:` is a same-project entity ref — exactly as `plugin-mise` already owns its `check-mise-*` bed images.
- **`.github/workflows/deploy.yml`** — CI charly pin `v2026.238.1242` → `v2026.256.1316`. **WHY:** the old pin predates the `2026.249.2125` schema stamp this PR introduces and rejects it, so the stock candy CI's `charly box validate` cannot load the repo; `v2026.256.1316` is the tag that accepts the stamp (the same pin the sibling relocation PRs use). No other CI logic changes.
- **`.gitignore`** (new) — ignores generated build/eval artifacts the relocated bed produces: `.build/`, `.containerignore`, `.dockerignore`, `.check/`, `output/`, editor scratch, and `charly migrate` rollback backups (`*.bak`, `*.bak.*`). Without it the bed's build context and eval scratch would dirty the repo.

**WHY relocate.** A check bed must live in the repo that owns what it tests. The `check-pod` bed's subject is the pod runtime/mechanism this plugin implements (kind:pod lifecycle, supervisord keepalive, deploy-target rendering) — not the distro whose base image the fixture happens to build on. It sat in `distro-fedora` only because the 2026-06 box inversion grouped boxes into distro repos by base image.
